# ADR-0005 — Память в репо через нативный механизм

## Контекст

Память агента (уроки, правила работы, устойчивые факты о контуре) по умолчанию лежит вне проекта и потому не переживает смену машины и не попадает в review. При этом писать свой слой синхронизации ради этого — заводить рантайм там, где хватает конфигурации.

## Решение

**Каталог памяти переносится в vault** (`70-memory/`) штатной настройкой гарнитуры `autoMemoryDirectory` в `.claude/settings.json`. Git выступает синхронизацией и резервной копией; отдельных sync-хуков нет.

- Одна память — один файл — один факт, с frontmatter (`type: user | feedback | project | reference`).
- `70-memory/MEMORY.md` — индекс: строка на память, загружается в контекст каждой сессии.
- Память ревьюится как код: она в тех же коммитах и попадает под те же гейты.

## Альтернативы

- **Память по умолчанию (вне репо)** — отклонён: нарушает INV-1, теряется при переустановке, не видна в истории.
- **Свой скрипт синхронизации из `~/.claude` в vault** — отклонён: рантайм ради того, что делает одна строка настройки (INV-7); две копии расходятся молча.
- **Память как обычные заметки без нативного механизма** — отклонён: агент не подхватывает их автоматически, значит правило вспоминается только когда о нём и так помнят.

## Последствия

- **+** Память переносима, versioned и предъявима.
- **+** Ноль своего кода.
- **−** Настройка указывает на путь установки — при переносе vault в другой каталог её правят руками (единственный не-переносимый параметр, отмечен в `README`).
- **−** Память попадает в тот же репозиторий, что и рабочие данные: правило INV-22 (ссылки, не значения) распространяется и на неё.
