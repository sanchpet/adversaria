# ADR-0012 — Плагины Obsidian не вендорятся в git

## Контекст

Obsidian — часть системы, а не просмотрщик: properties, dataview, Bases и Templater несут проекции и формы (INV-11, INV-18). Значит конфигурация плагинов есть состояние системы. Вопрос — попадает ли в репозиторий их **код**.

Вендоринг даёт воспроизводимость на машине без доступа к каталогу сообщества. Цена — десятки мегабайт стороннего JavaScript в репозитории, который придётся ревьюить и обновлять руками.

## Решение

**В git идёт конфигурация, не код плагинов.**

- Трекается: `core-plugins.json`, `community-plugins.json` (список), `app.json`, `appearance.json`, `graph.json`, `hotkeys.json`, `types.json`, `snippets/`.
- Игнорируется: `.obsidian/plugins/**` (код), `.obsidian/themes/**`, `workspace.json` (состояние UI, меняется постоянно).
- Список плагинов и порядок установки — в `README`; ставятся при первом развёртывании.

**Оговорка о закрытом контуре.** Если каталог сообщества недоступен с рабочей машины, вендоринг становится оправданным — но как **осознанное локальное отклонение** в рабочем репозитории, а не свойство шаблона. Шаблон остаётся лёгким.

## Альтернативы

- **Вендоринг кода плагинов** — отклонён для шаблона: сторонний JavaScript в репозитории, который никто не ревьюит, плюс объём, делающий клон тяжёлым ради разовой установки.
- **Не трекать `.obsidian` вовсе** — отклонён: тогда проекции, сниппеты и раскладка свойств восстанавливаются вручную, то есть не восстанавливаются (нарушает INV-1 в той части, где Obsidian несёт функцию).
- **Трекать всё, включая `workspace.json`** — отклонён: файл меняется от каждого открытия панели и заливает историю шумом.

## Последствия

- **+** Клон лёгкий; сторонний код в репозиторий не попадает.
- **+** Конфигурация и сниппеты воспроизводятся из коробки.
- **−** Первое развёртывание требует установки плагинов руками (один раз, по списку в `README`).
- **−** Версии плагинов не зафиксированы: обновление может поломать проекцию. Симптом лечится откатом плагина, не откатом vault.
