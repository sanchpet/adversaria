# ADR-0010 — Конфиг установки (`80-kernel/config.md`)

## Контекст

Часть параметров не выводится ни из кода, ни из состояния: как называется трекер, по какому шаблону строится URL тикета, какие часы считаются рабочими, какие репозитории клонируются. Скиллы должны читать их детерминированно, а не спрашивать каждый раз.

## Решение

**Один файл `80-kernel/config.md`, секциями** — параметры установки под конкретного инженера и конкретного работодателя. Это же единственное место, которое правится при развёртывании шаблона.

**Правило дробления:** расщеплять на отдельные файлы — когда второй скилл-потребитель захочет свой срез **и** файл вырастет настолько, что чтение целиком стоит контекста. Триггер не «второй потребитель» сам по себе. До тех пор каталог `config/` — преждевременная структура (INV-3).

Принцип: **дробить конфиг по потребителю, не по теме** — цена контекста есть число файлов, которые скилл вынужден прочитать ради нужного среза.

## Альтернативы

- **Параметры в `settings.json`** — отклонён: смешивает доменный конфиг с конфигом гарнитуры, json не читается в Obsidian и не комментируется.
- **Параметры в памяти `70-memory/`** — отклонён: память служит выборочному recall, конфиг читается детерминированно и целиком; мискатегоризация.
- **Инлайн в скиллах** — отклонён: один и тот же параметр расползается по нескольким скиллам и расходится.
- **Каталог `config/` сразу** — отклонён: структура под нагрузку, которой нет.

## Последствия

- **+** Развёртывание шаблона сводится к правке одного файла.
- **+** Смена трекера = правка одной секции, не поиск по дереву.
- **−** Конфиг лежит в репозитории: правило INV-22 (ссылки и имена, не значения) действует и здесь — ключей и токенов в нём быть не может.
