# ADR-0011 — FPF как submodule, без внешнего MCP

## Контекст

Методология первых принципов нужна в рабочей сессии: обоснование решений, строгие различения, сравнение вариантов по одинаковым критериям. Подключить её можно двумя путями — локальной копией под git или удалённым сервисом семантического поиска.

На корпоративном контуре второй путь несёт цену, которой нет на личном: внешний эндпоинт, авторизация в стороннем сервисе и отправка рабочего запроса наружу. Это отдельный разговор с ИБ ради удобства поиска.

## Решение

**Только `.principles/fpf` как git-submodule**, только чтение, поиск — `Grep`/`Read` по локальным файлам. Внешний MCP-сервис методологического корпуса **не подключается**.

- Обновление — по нужде: `git submodule update --remote .principles/fpf`.
- Скилл `/fpf` работает исключительно от локального submodule; режима семантического поиска у него нет.
- **No-Jargon (INV-6):** каждый термин фреймворка в выводе сопровождается инженерным эквивалентом. Таблица перевода — `.principles/README.md`.
- Слои поверх FPF (формализация доменов по методологии второго уровня) в этот контур не переносятся: домен работы описывается свободно в `30-knowledge/`, без обязательной формы.

## Альтернативы

- **Submodule + внешний MCP** — отклонён: рабочий запрос уходит на сторонний сервис; выигрыш (семантический поиск вместо grep) не оправдывает разговора с ИБ и внешней зависимости в сессии.
- **Вендоринг выжимки в `80-kernel/`** — отклонён: копия застывает и молча расходится с апстримом; submodule даёт ту же офлайн-доступность с зафиксированной и обновляемой версией.
- **Без методологического слоя** — отклонён: `/think` и `/archgate` опираются на конкретные паттерны (цикл гипотез, сравнение по одинаковым критериям), и без источника они вырождаются в свободное рассуждение.

## Последствия

- **+** Офлайн, версия зафиксирована коммитом, наружу ничего не уходит.
- **+** Чистый клон воспроизводит слой одной командой.
- **−** Поиск по подстроке вместо семантического: формулировка запроса требует знания терминологии.
- **−** Submodule тянется с публичного хоста — на закрытом контуре зеркалится во внутренний git (см. `README`).
