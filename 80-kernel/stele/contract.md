# Контракт рабочего vault — инварианты

> Канонический источник инвариантов системы. Ссылки `INV-N` в `CLAUDE.md`, ADR-Стеле и `70-memory/` разрешаются здесь.
> Контракт-first: инварианты — обещания-outcomes (полярность «больше-лучше»), не механика. Механика живёт в ADR, скиллах и хуках и меняется, не трогая обещания.

> **О нумерации.** Ряд идёт с пропусками (нет INV-8, 10, 12, 13, 15, 20, 21). Это подмножество более широкого набора, из которого система выведена; номера **не переиспользуются**, чтобы формулировки не разъезжались при переносе знания между контурами. Пропуск = «этого обещания система не даёт», а не «забыли».

## Базовые (INV-1…7)

- **INV-1 Переносимость** — состояние (память / планы / карточки задач / знание) восстановимо из чистого клона vault без спец-рантайма. Единственные внешние зависимости объявлены явно: git, Obsidian, агент.
- **INV-2 OwnerIntegrity** — один предмет знания живёт в одном месте в любой момент. Трекер — system of record по **состоянию** задачи; vault — по **рабочей канве**. Дублировать состояние из трекера в карточку запрещено.
- **INV-3 Леность контекста** — несётся только добавленное инженером; без балласта «по умолчанию». Пустая секция не разворачивается, преждевременный каталог не заводится.
- **INV-4 Прямая правка субстрата** — агент пишет md напрямую; MCP-прослойка к Obsidian не нужна; properties/dataview работают из коробки.
- **INV-5 Гейты-инварианты** — Открытие / Закрытие / capture обеспечены хуками и скриптами, а не памятью инженера. Правка самого гейта — осознанный акт с ADR, не правка по ходу.
- **INV-6 Инженерные дефолты** — словарь, гейты и умолчания рассчитаны на инженера. Термин методологического фреймворка в выводе сопровождается инженерным эквивалентом; режим «на пальцах» — только по явному запросу.
- **INV-7 Минимальная поверхность** — нет своего рантайма, нет обобщений «на любого пользователя», нет апстрим-синхронизации. Внешняя методология подключается как read-only референс (submodule), не как хостируемый сервис.

## Ритм (INV-9)

- **INV-9 ОРЗ-фрактал** — Открытие → Работа → Закрытие на трёх масштабах: **сессия** (`/checkpoint`), **день** (`/open` … `/close`), **неделя** (свод в закрытии пятницы). Облегчённо: ритуал, который не помещается в реальное окно рабочего дня, не исполняется и потому не вводится. Незакрытый день — **детектируется** (носитель — INV-17).

## Поверхности и доменная модель (INV-11, 14)

- **INV-11 Стартовая страница** — обязательная проекция фокуса (активные задачи, проекты, разрывы) через properties / dataview / Bases. Это **место-вид, не источник**: проекция читает frontmatter карточек и ничего не хранит.
- **INV-14 Реестр + трассировка** — два реестра: **проекты** и **задачи**. Каждая карточка задачи трассируется на проект и на тикет трекера; каждый проект — на цель работодателя, названную своими словами. Разрыв трассировки (задача без проекта, проект без цели) — **детектируется**, а не запрещается: разрыв бывает честным сигналом, что работа пришла мимо цели.

## Поток знаний (INV-2 producer, INV-19 writer)

- **INV-19 Writer-ownership** — один writer на файл: **agent-writer** (состояние, реестры, карточки — через агента) либо **engineer-writer** (проза, черновики — в Obsidian) либо **mixed** (исключение, объявляется во frontmatter полем `writer` и держит внутрифайловую границу зон: агент ведёт таблицу состояния, инженер ведёт прозу). `mixed` ≠ «ничей».

## Поведение агента (INV-16)

- **INV-16 Мышление / регистр** — рассуждение поверх первых принципов (FPF) с инженерным тоном по умолчанию. Агент **проверяет, а не верит**: утверждение о состоянии системы подкрепляется выводом команды или логом, не памятью. Чтение правила, конфига или доки подкрепляет утверждение **о тексте**, а не о поведении: «заблокировано», «запрещено», «невозможно» суть утверждения о поведении, и доказывает их только команда, заставившая систему себя повести.

## Инженерная дисциплина (INV-17, 18)

- **INV-17 Система-как-код** — vault лежит в git, поэтому к нему самому применяются pre-commit, проверки и code-review. Носитель энфорсмента для INV-5 / 14 / 18 / 19. При n=1 review = самопроверка или проверка свежим суб-агентом (`/verify`).
- **INV-18 Naming + native-first** — конвенция имён (см. ADR-0003) плюс правило build-vs-adopt: фича Obsidian (wikilinks / properties / dataview / Bases) или гарнитуры агента идёт раньше собственной реализации. Своё пишем, только когда нативного нет.

## Безопасность (INV-22)

- **INV-22 Граница корпоративных данных** — в vault попадают **ссылки и пути**, а не значения: URL тикета, путь в хранилище секретов, имя сервиса. **Никогда** — токены, пароли, ключи, персональные данные людей, выгрузки клиентских данных. Правило действует независимо от приватности репозитория: приватность есть контроль доступа, а не право хранить что угодно.

## Anti-scope

Не дистрибутив, не платформа для команды, не замена трекеру и не второй трекер. Контракт — личный рабочий инструмент одного инженера.
