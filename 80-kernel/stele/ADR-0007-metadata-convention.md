# ADR-0007 — Конвенция метаданных

## Контекст

Проекции (стартовая страница, доска задач, детекторы разрывов) читают frontmatter. Если род заметки и её статус пишутся как придётся, проекция либо теряет записи молча, либо требует всё более хитрых запросов.

## Решение

**Два обязательных свойства несут семантику: `type` (род) и `status` (состояние).** Остальные поля — по роду.

| `type` | Где живёт | Допустимые `status` |
|---|---|---|
| `task` | `10-governance/tasks/` | `in-progress` `blocked` `done` `later` |
| `project` | `10-governance/projects/` | `active` `paused` `done` |
| `session` | `10-governance/sessions/` | — |
| `dayplan` | `10-governance/plans/` | — |
| `note` `draft` | `20-library/` | `later` `in-progress` `processed` `done` |
| `knowledge` | `30-knowledge/` | `later` `in-progress` `processed` |
| `adr` | `80-kernel/stele/` | `proposed` `accepted` `superseded ADR-NNNN` `withdrawn` |
| `system` `config` | `80-kernel/` | — |
| `registry-index` | корень (`start.md`) | — |

- Род без схемы статусов в таблице статус **не проверяет** — правила не выдумываются под роды, где состояния нет.
- `aliases` несут человекочитаемое (в том числе кириллическое) имя — см. ADR-0003.
- **Энфорсмент** — `frontmatter-check.py` в pre-commit: YAML-валидность (ловит битые кавычки, которые Obsidian показывает как invalid properties) + схема статусов.

## Альтернативы

- **Теги вместо свойств** — отклонён: тег не типизирован, не даёт enum и не сортируется; dataview по свойствам строит таблицы, по тегам — списки.
- **Свободные статусы** — отклонён: проекции начинают ловить `in progress`, `In-Progress` и `wip` как три разных состояния.
- **Валидация только в агенте** — отклонён: правка руками в Obsidian мимо агента остаётся неохваченной, а именно там опечатки и возникают.

## Последствия

- **+** Проекции строятся на предсказуемом наборе полей.
- **+** Ошибка ловится на коммите, а не при следующем открытии доски.
- **−** Новый род требует правки таблицы и скрипта — намеренное трение: род заводится осознанно.
