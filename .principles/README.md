# .principles — первые принципы

> Dot-зона: Obsidian её игнорирует. Методологический источник как git-submodule — референс по нужде, не хостируемый рантайм (INV-7). Содержимое submodule не правим, только ссылаемся.

## Что подключено

| Слой | Submodule | Что это | Upstream |
|---|---|---|---|
| Первые принципы | `fpf/` | First Principles Framework: базовые различения (границы систем, роли, отношение «часть-целое», цикл гипотез, уровни доверия к данным) | `github.com/ailev/FPF` |

**Только FPF, только локально.** Внешний сервис семантического поиска по методологическому корпусу в этом контуре не подключается — рабочий запрос не должен уходить на сторонний эндпоинт ([[ADR-0011-fpf-submodule-no-mcp|ADR-0011]]). Слои поверх FPF (формализация доменов по методологии второго уровня) сюда не переносятся: знание о работе живёт в `30-knowledge/` свободной формой.

Скилл `/fpf` работает исключительно от этого каталога.

## No-Jargon: перевод в инженерный язык

> Правило INV-6: в выводе каждый термин фреймворка сопровождается инженерным эквивалентом. Неизвестный термин — перевести по контексту и пометить `(FPF: <оригинал>)`.

| Термин FPF | Инженерный эквивалент | Где встретишь |
|---|---|---|
| Holon | Компонент с границей (одновременно часть и целое) | A.1 — декомпозиция |
| Bounded Context (A.1.1) | Контекст с чёткими границами: свой язык, свои правила | DDD, микросервисы |
| F-G-R (Fact / Guess / Rumor) | Факт / предположение / слух — уровень доверия к данным | B.3 — оценка решений |
| Role ≠ Method ≠ Work (A.7) | Кто делает ≠ как делает ≠ конкретное выполнение | проектирование процессов |
| Role Assignment (A.2.1) | Система-в-роли; роль сама по себе не работает | онтология ролей |
| Service Polysemy (A.6.8) | Сервис = обещание + роль + метод + работа + свидетельства | дизайн сервисов |
| Alpha | Ключевой рабочий продукт, по которому виден прогресс | управление работой |
| Mereology | Отношение «часть — целое» | архитектура, композиция |
| Affordance | Что компонент позволяет делать пользователю | API, UX |
| ADI-цикл (B.5) | Гипотеза → проверка логикой → проверка данными | принятие решений |
| Lawful Comparison (A.19) | Сравнение вариантов по одинаковым критериям | выбор архитектуры |
| Strict Distinction (A.7) | Разные вещи — разные имена; не смешивать в одном типе | ревью, именование |

## Работа с submodule

```bash
# на чистом клоне
git submodule update --init --recursive

# обновить до свежего upstream (по нужде, не по расписанию)
git submodule update --remote .principles/fpf
```

**На закрытом контуре**, где публичный GitHub недоступен, submodule зеркалится во внутренний git и `url` в `.gitmodules` меняется на зеркало. Это локальное отклонение рабочего репозитория, а не свойство шаблона.
