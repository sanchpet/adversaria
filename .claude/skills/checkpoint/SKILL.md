# /checkpoint — Закрытие сессии

Самый частый масштаб ритма: закрыть сессию внутри дня, ничего не потеряв. Три минуты, не больше.

1. **Коммит** — `git status` → `git add <конкретные пути>` → commit. Не потерять. Пуш — по правилам git-дисциплины, не автоматически.

2. **Capture** — появилось знание за сессию? Маршрутизировать как в `/close`: решение → ADR; урок → `70-memory/`; знание → `30-knowledge/`; семя текста → `20-library/`. Нет нового — пропустить молча.

3. **Handoff — в два адреса, и они несут разное.**
   - **Карточка задачи** — следующий шаг и контекст, которого не будет в голове через час. Это дешевле, чем восстанавливать его потом.
   - **Журнал дня** (`10-governance/sessions/YYYY-MM-DD.md`, секция «Сделано») — строка-две о том, что сдвинулось за сессию. Не пересказ карточки: журнал хронологичен и отвечает на вопрос «чем был день», карточка — на вопрос «где эта задача».

   **Отказ, который ловит вторая строка:** без неё `/close` восстанавливает день по коммитам. Это работает, только пока каждый коммит атомарен и несёт «почему», и молча теряет всё, что коммита не произвело — разговор, замер, отвергнутую гипотезу.

Сессия ≠ день: `/close` самодостаточен, внутри него `/checkpoint` не повторять. Пропуск сессии не детектируется — масштаб текучий; главное ловит коммит.
