# /task — завести карточку задачи

Работа: $ARGUMENTS

> Метод — `80-kernel/docs/task-discipline.md` (источник, здесь не дублируется). Карточка — ОДНА self-contained единица; реестр и доску собирают проекции. Никакой записи в несколько мест.

## Шаг 0. Гейт (БЛОКИРУЮЩЕЕ — до создания)

1. **Тикет.** Есть идентификатор в трекере? Нет — либо завести тикет, либо оставить запись в `00-inbox/`. **Карточку без тикета не заводить**: собственная нумерация дала бы второй идентификатор одной работы, и они разойдутся на первом же обсуждении с коллегой.
2. **Предъявимый артефакт.** Что предъявишь как доказательство, что работа сделана — репозиторий, коммит, конфиг, развёрнутый сервис, документ, дашборд, разбор с выводом? «Разобрался / посмотрел / поработал» — деятельность, не результат. Нет ответа → карточки нет.
3. **Задача ≠ проект.** Артефакт размытый, охватывает много разных выходов → это **проект** из нескольких задач. Предложить завести проект в `10-governance/projects/` и разложить по тикетам, а не лепить одну карточку.
4. **Порог.** Работа переживает одну сессию? Иначе она живёт в трекере и умирает там же.
5. **Трассировка.** На какой проект работает? Разрыв не блокирует, но называется вслух: задача мимо всех проектов — сигнал, что работа пришла мимо того, чем ты считаешь себя занятым.

Гейт пройден → **предложить формулировку и дождаться подтверждения**. Заведение карточки — осознанный акт, не автоматизм.

## Шаг 1. Карточка

Скопировать `80-kernel/scaffolds/task-tmpl.md` → `10-governance/tasks/<ticket>.md` (имя **строчное**, ADR-0003).

Заполнить frontmatter: `ticket`, `title`, `tracker_url` (по шаблону из `80-kernel/config.md`), `project`, `status`, **`artifact`** (без него хук заблокирует), `verification_class`, `opened`.

Тело: постановка **своими словами** (не копия описания тикета — если своими словами не выходит, задача ещё не понята), диагностика с доказательством, подготовленные правки, DoD.

## Шаг 2. Подтверждение

«Карточка `<ticket>` заведена. Артефакт: `<…>`. Класс верификации: `<…>`. Проект: `<…>`.»

Класс верификации определяет глубину приёмки ([[task-discipline]], «Приёмка: артефакт против DoD») и как задачу вести: **open-loop** держим живым деревом и не выдумываем ему критический путь; **problem-framing** выходит через `/archgate`.
