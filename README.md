# Adversaria

Рабочий экзокортекс инженера: markdown-vault под git, который открывается Obsidian и правится агентом напрямую.

*Adversaria* (лат.) — рабочая тетрадь, куда записывают по ходу дела, чтобы позже перегнать в чистовое. Это и есть функция системы: захват по ходу, триаж, перегонка в знание и в предъявимый результат.

**Что система делает.** Единицу учёта работы назначает работодатель — это тикет в трекере, и трекер хранит состояние deliverable хорошо. Здесь живёт то, чего он не хранит: рабочая канва (что пробовал, чем доказал, где застрял, с чего начать завтра), знание о предметной области и решения с обоснованием.

**Чем система не является.** Не вторым трекером. Перенос полей из трекера в карточку — главная ошибка, которую здесь можно совершить.

Этот репозиторий — **шаблон**: машинерия без данных. Разворачивается копией, наполняется на месте.

## Развёртывание

```bash
git clone --recurse-submodules <url> adversaria
cd adversaria

# 1. Гейты на коммит (frontmatter, карточки задач, секреты)
pre-commit install

# 2. Плагины и тема Obsidian — код не вендорится (ADR-0012), ставится один раз
#    Настройки → Community plugins → установить по списку .obsidian/community-plugins.json:
#      dataview · templater-obsidian · homepage · obsidian-git
#      obsidian-auto-link-title · url-into-selection · obsidian-excalidraw-plugin
#      obsidian-style-settings · copy-url-in-preview
#    Настройки → Appearance → Themes → установить Retroma
#      (appearance.json уже указывает на неё; style-settings нужен именно теме)
#    Templater: папка шаблонов → 80-kernel/templates
#    Homepage: стартовая страница → start.md
```

Дальше правится **четыре места** — и больше ничего:

1. **`80-kernel/config.md`** — трекер (имя, шаблон URL тикета, форма идентификатора, префиксы проектов), ритм (рабочие часы, часовой пояс, день закрытия недели, реальная ёмкость дня), репозитории, профиль агента.
2. **`.claude/settings.json` → `autoMemoryDirectory`** — фактический путь до `70-memory/` этого клона. Единственный непереносимый параметр (ADR-0005).
3. **`80-kernel/stele/*.md` → `created: <YYYY-MM-DD>`** — даты принятия ADR. Решение без даты — не решение, а мнение.
4. **Первый проект** — `10-governance/projects/` из `80-kernel/scaffolds/project-tmpl.md`. Без единого проекта трассировка задач висит в воздухе.

Проверка, что гейты живы:

```bash
bash 80-kernel/scripts/orz-check.sh      # молчит, когда всё закрыто
pre-commit run --all-files
```

## Как этим работать

| | |
|---|---|
| Начало дня | `/open` — детектор ритма, вчерашний журнал, триаж инбокса, DayPlan |
| Внутри дня | `/checkpoint` перед перерывом или переключением — коммит, capture, handoff |
| Новая работа | `/task` — гейт решит, нужна ли карточка |
| Результат готов | `/verify` — проверка свежим суб-агентом по эталону |
| Развилка | `/think` → при архитектурном решении `/archgate` → ADR |
| Упёрся в понятие | `/fpf` |
| Текст для коллег | `/corp-docs` — вики, README рабочего репозитория, RFC, разбор инцидента |
| Не хватает инструмента | `/env` (своё окружение через dotfiles) · `/skill-add` (чужой скилл, с разведкой до установки) |
| Конец дня | `/close` — итоги, capture, статусы, «завтра начать с» |

Каталог скиллов и сцепки — `80-kernel/docs/skills.md`. Дисциплина задач — `80-kernel/docs/task-discipline.md`.

## Три правила, которые держат систему

**Тикет — единственный идентификатор работы.** Собственная нумерация не заводится: два идентификатора одной работы расходятся на первом же обсуждении с коллегой (ADR-0006).

**Карточка не заводится без предъявимого артефакта.** Что покажешь как доказательство, что работа сделана? «Разобрался» показать нельзя. Гейт блокирующий — в хуке агента и в pre-commit.

**Ссылки и пути — да, значения — нет.** URL тикета, путь в хранилище секретов, имя сервиса — записываем. Токены, ключи, пароли, персональные данные, выгрузки клиентских данных — никогда, независимо от приватности репозитория (INV-22). Второй рубеж — `gitleaks` на коммите.

## Зависимости

git · Obsidian · агент · `pre-commit` · `python3` (гейты) · доступ к `github.com/ailev/FPF` для submodule.

На закрытом контуре submodule зеркалится во внутренний git, `url` в `.gitmodules` меняется на зеркало; если каталог плагинов Obsidian недоступен — плагины вендорятся локально как осознанное отклонение от ADR-0012.

## Происхождение

Извлечено из личной системы того же владельца как отдельная ветвь развития под наёмную работу. Что осталось за границей и почему: личный governance (собственные направления и неудовлетворённости — у наёмной работы корень целей принадлежит работодателю), стратегирование от личных целей, ведение источников обучения, творческий конвейер письма, методология поверх первых принципов, внешние сервисы знания.

Ветви расходятся: общего кода у них нет, обратного слияния не предполагается.
